**TITAN (Typhoon Intensity and Track Analytics Network)** is an end-to-end deep learning framework designed to forecast the evolution of tropical cyclones. This project demonstrates the power of fusing historical storm tracks with environmental reanalysis data to train a single, unified neural network that simultaneously predicts a typhoon's future **track**, **intensity**, and the **probability of Rapid Intensification (RI)**.

## Key Features

- **End-to-End Workflow:** The entire project, from data acquisition to final evaluation, is contained within two streamlined Google Colab notebooks.
- **Multi-Modal Data Fusion:** Integrates time-series storm history with static environmental data to create a comprehensive feature set.
- **Multi-Task Learning:** A single model simultaneously predicts three distinct forecasting targets (Track, Intensity, and RI Probability) up to 72 hours in advance.
- **Advanced Architecture:** Implements a multi-input model using an LSTM to capture temporal dynamics and a DNN for environmental analysis.

## Technical Deep Dive: The TITAN Framework

This section provides a detailed explanation of the project's data pipeline, feature engineering, model architecture, and training methodology.

### 1. Data Pipeline and Feature Engineering

The foundation of the TITAN model is a robust data pipeline that transforms raw historical records into a feature-rich dataset suitable for deep learning.

**Data Sources:**
- **IBTrACS (International Best Track Archive for Climate Stewardship):** Provides the "ground truth" for storm history, including 6-hourly records of position (latitude, longitude) and intensity (max sustained wind, min central pressure).
- **ERA5 Reanalysis Dataset:** Sourced via the Copernicus Climate Data Store (CDS) API, this provides a global grid of atmospheric and oceanic environmental data.

**Pipeline Steps:**
1.  **Collocation:** For every 6-hourly data point in the filtered IBTrACS dataset, a corresponding set of environmental variables was programmatically downloaded from the ERA5 dataset. The script fetches data for the exact time and interpolates it to the storm's central location.
2.  **Environmental Feature Calculation:** Key physical predictors were calculated from the raw ERA5 variables, most notably:
    - **Vertical Wind Shear (VWS):** The magnitude of the vector difference between winds at 200hPa and 850hPa. High VWS is a critical inhibitor of storm intensification.
3.  **Temporal Feature Engineering:** To provide the model with a memory of the storm's recent behavior, a set of lagged features were created for each data point:
    - **History Window:** A 24-hour look-back period was used, creating 4 time steps (t-6h, t-12h, t-18h, t-24h).
    - **Lagged Variables:** Past values of `LAT`, `LON`, `WMO_WIND`, `WMO_PRES`, and the storm's own translation vector (`U_STORM`, `V_STORM`) were included.
4.  **Target Label Generation:** The "answers" for the model to learn were generated by looking ahead in the storm's track:
    - **Track & Intensity Labels:** Future `LAT`, `LON`, and `WMO_WIND` were included for lead times of +6, +12, +24, +48, and +72 hours.
    - **RI Label:** A binary label was created, defined as `1` if the storm's wind speed increased by **7 m/s or more** within the next 12 hours, and `0` otherwise.

### 2. Model Architecture: A Multi-Input, Multi-Head Design

The TITAN model is a multi-input, multi-head neural network built in TensorFlow/Keras, designed to process heterogeneous data streams effectively.

- **Input Branch 1: Temporal (LSTM)**
  - **Input:** A sequence of the storm's last 4 historical states (24 hours). The input shape is `(None, 4, 6)`, representing 4 time steps with 6 features each.
  - **Layers:** An `LSTM` layer with 32 units processes this sequence.
  - **Purpose:** This branch is specialized to understand the storm's internal dynamics, momentum, and recent trends (e.g., acceleration, intensification rate).

- **Input Branch 2: Static (DNN)**
  - **Input:** A flat vector containing ~15 current-state and environmental features (e.g., current LAT/LON, SST, VWS, RH).
  - **Layers:** A `Dense` network (64 units -> 32 units, with 'ReLU' activation).
  - **Purpose:** This branch learns the complex, non-linear relationships between the storm's immediate environment and its future potential.

- **Fusion Layer:**
  - The output vectors from both the LSTM and DNN branches are **concatenated**. This creates a single, rich feature vector that combines both the storm's historical context and its present environmental conditions. This fused vector is then passed through a final `Dense` layer (64 units, 'ReLU') for final-stage feature learning.

- **Multi-Head Output:**
  The model splits into three independent output heads, allowing each to specialize in its task:
  1.  **Track Head:** A `Dense` layer with 10 linear neurons, outputting the `LAT` and `LON` for the 5 forecast lead times.
  2.  **Intensity Head:** A `Dense` layer with 5 linear neurons, outputting the `WMO_WIND` for the 5 forecast lead times.
  3.  **RI Head:** A `Dense` layer with a single neuron and a `sigmoid` activation, outputting the probability of RI (a value between 0 and 1).

### 3. Training Methodology

The model was trained using a set of best practices to ensure robust and reliable performance.

- **Data Splitting:** The dataset was split chronologically into training and validation sets. This is a critical step for time-series data to prevent the model from "seeing the future" and to provide a realistic evaluation of its generalization capabilities.
- **Data Scaling:** All input features (both temporal and static) were standardized using `StandardScaler`. The scaler was `fit` **only** on the training data and then used to `transform` both the training and validation sets to prevent data leakage.
- **Composite Loss Function:** The model was compiled with a composite loss function that combined the losses from all three heads. This allows the model to learn all tasks simultaneously.
  - **Track & Intensity Loss:** `Mean Squared Error (MSE)`, suitable for regression tasks.
  - **RI Loss:** `Binary Cross-Entropy`, the standard for binary classification tasks.
  - **Loss Weights:** The RI loss was given a higher weight to encourage the model to pay closer attention to this rare but critical event.
- **Optimization:** The `Adam` optimizer was used.
- **Regularization:** `EarlyStopping` was implemented to monitor the validation loss. Training was automatically stopped after 10 epochs with no improvement, and the weights from the best-performing epoch were restored, effectively preventing overfitting.


## Final Results

The final model, trained on over 40,000 data points, demonstrated a dramatic improvement over the initial prototype and showed highly competitive performance.

## Getting Started

This project is designed to be run entirely within Google Colab. The workflow is divided into two main notebooks.

### Prerequisites

1.  **Google Account:** Required to use Google Colab and Google Drive.
2.  **Copernicus CDS Account:** You must register for a free account at the [Copernicus Climate Data Store (CDS)](https://cds.climate.copernicus.eu/user/register) to get an API key. This is needed for downloading the environmental data.
3.  **IBTrACS Data File:** Download the `ibtracs.ALL.list.v04r00.csv` file and place it in a Google Drive folder (e.g., `MyDrive/Colab_Data/`).

### Usage Instructions

Follow the notebooks in order.

**1. `Data_Preparation.ipynb`**
   - **Purpose:** This notebook handles all data acquisition and preparation steps (Phases 1, 2, and 3).
   - **Steps:**
     1. Mounts your Google Drive to access the IBTrACS CSV.
     2. Cleans and filters the initial storm track data.
     3. Prompts for your CDS API key to download the ERA5 environmental data. **(This is a long-running step, ~5-8 hours).**
     4. Performs feature engineering to create lags and labels.
     5. Saves the final, model-ready dataset (`df_model_ready_full.csv`) to your Google Drive.

**2. `Model_Training_and_Evaluation.ipynb`**
   - **Purpose:** This notebook handles all modeling and evaluation steps (Phases 4 and 5).
   - **Steps:**
     1. Loads the final, model-ready dataset from your Google Drive.
     2. Defines, compiles, and trains the TITAN neural network.
     3. Saves the trained model file (`typhoon_forecast_model.h5`).
     4. Evaluates the model's performance on the test set and generates the final metrics and visualizations.

## Limitations and Future Work

**Limitations:**
- The model's performance is dependent on the quality of the historical reanalysis data.
- It is a proof-of-concept and not an operational, real-time system.
- The model does not provide explicit, physics-based reasoning for its forecasts (the "black box" problem).

**Future Work:**
- Develop a pipeline for real-time data ingestion to create an operational prototype.
- Incorporate additional data sources, such as satellite imagery (via a CNN branch).
- Implement model interpretability techniques (e.g., SHAP) to understand the key drivers behind the model's predictions.
